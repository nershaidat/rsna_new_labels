KNEE MRI MIL12 v1
=================

This is the first model version that treats all 12 abnormalities jointly while
respecting the MRI hierarchy:

    Study -> Series -> Slices

Targets
-------
ACL
MCL
Medial Meniscus
Lateral Meniscus
Medial OA
Lateral OA
PF OA
Effusion
Synovitis
Baker's
Contusion
Fracture

Why this is MIL rather than slice classification
------------------------------------------------
A study-level report-derived label is not copied to every slice. The model
learns target-specific attention over slices and over series, then predicts
12 probabilities at the study level.

Treatment of p = 0.5
--------------------
p = 0.5 means "not addressed / no useful evidence".

The label remains 0.5, but its information weight is:

    w = 2 * abs(p - 0.5)

Therefore:

    p      w
    0.0    1.0
    0.2    0.6
    0.3    0.4
    0.5    0.0
    0.7    0.4
    0.8    0.6
    1.0    1.0

This prevents an unknown report item from acting like a negative slice/study
label or artificially forcing the network toward 0.5.

Input 1: census
---------------
Use the SQLite checkpoint generated by knee_mri_census_v2.py, e.g.

  /mnt/y/data_RSNA_4_Study/results/knee_mri_census.xlsx.checkpoint.sqlite

Input 2: weak labels
--------------------
Save the Excel workbook that contains the VBA-created WeakLabels sheet.

The script expects StudyInstanceUID plus either:

  ACL_P, MCL_P, ..., Fracture_P

or:

  ACL, MCL, ..., Fracture

Audit first
-----------
Run this before decoding any MRI pixels:

python knee_mri_mil12_v1.py audit \
  --census "/mnt/y/data_RSNA_4_Study/results/knee_mri_census.xlsx.checkpoint.sqlite" \
  --labels "/mnt/y/data_RSNA_4_Study/WeakLabels.xlsx" \
  --labels-sheet "WeakLabels" \
  --run-dir "/mnt/y/data_RSNA_4_Study/results/mil12_v1"

It creates:
  split.csv
  series_manifest.csv
  study_manifest.csv
  label_summary.csv

Training
--------
Start conservatively:

python knee_mri_mil12_v1.py train \
  --census "/mnt/y/data_RSNA_4_Study/results/knee_mri_census.xlsx.checkpoint.sqlite" \
  --labels "/mnt/y/data_RSNA_4_Study/WeakLabels.xlsx" \
  --labels-sheet "WeakLabels" \
  --run-dir "/mnt/y/data_RSNA_4_Study/results/mil12_v1" \
  --epochs 20 \
  --max-series 8 \
  --slices-per-series 12 \
  --freeze-encoder \
  --num-workers 0 \
  --precision bf16

Why --num-workers 0 initially
-----------------------------
The user's WSL environment has previously filled /dev/shm during PyTorch
multiprocessing. Starting with 0 avoids that failure mode. Increase only after
the baseline runs reliably.

Outputs
-------
best.pt
last.pt
history.csv
best_val_metrics.csv
final_val_metrics.csv
test_metrics.csv (if test split nonempty)
val_attention_top_slices.csv

Attention audit
---------------
The attention CSV shows, separately for each abnormality, which series and
which sampled slices received the most attention.

This is NOT ground-truth lesion localization. It is a useful audit signal:
if the ACL model consistently attends to anatomically irrelevant series/slices,
that is a warning that the weak supervision or model is learning a shortcut.

Recommended development sequence
--------------------------------
1. Run audit.
2. Inspect label_summary.csv.
3. Inspect source distribution in split.csv.
4. Train with encoder frozen.
5. Inspect per-target validation metrics.
6. Inspect val_attention_top_slices.csv.
7. Only then consider unfreezing the CNN encoder.
